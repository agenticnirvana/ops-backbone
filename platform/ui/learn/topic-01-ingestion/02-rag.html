Retrieve, then generate

Retrieval-augmented generation pairs a model’s parametric memory (weights) with a non-parametric store (your documents). That store — usually a vector database — is the LLM’s long-term memory: facts you can update without retraining. At inference, relevant passages are fetched and the generator conditions on them.

weights = short-term · vector index = long-term

Intuition

Closed book vs open book

R look up the pages
A put them in context
G write from that context
Mechanics

What / why / how

What

Search the corpus first; generate second. Retrieval is a ranking problem. Generation is a language problem. Keep them separate.

Why

Policies change weekly. Weights do not. Lookup is cheaper than fine-tunes, and you can score whether the right passage returned.

How

Embed the query → top-k chunks (ANN, not a full scan) → prompt → generate. Optionally hybrid with keywords. Gate on similarity when the nearest neighbor is still the wrong domain.

In production

Where teams actually use it

Support & policy bots

Returns policy updates Tuesday; answers follow Wednesday. No retrain.

Repo / doc copilots

Pull the local API, not a random tutorial from 2019.

High-stakes drafts

Legal and clinical flows still need a human. RAG’s job is the right paragraph plus a citation.
