What we actually score

Five numbers per case, then an average. The gate reads the averages. LLM-as-judge is recorded beside them so you can trend quality without letting a verbose model veto a correct ID.

Mechanics

What / why / how

What

Recall@3 is retrieval. Correctness is the gated match after the similarity floor. They can disagree: nearest neighbor in top-3, still unmatched.

Why

A slow-query alert must not steal db-pool-exhausted. Unmatched + HITL is a pass. Forcing a catalog ID would teach the agent to hallucinate runbooks.

How

Fixtures declare expected_runbook_id (or none), keywords, expects_hitl. _case_passed is strict; the suite average is the gate.

In production

Same ideas, different names

Faithfulness

Did the answer stay inside retrieved context? Our groundedness is a cheap keyword cousin; the judge is the prose cousin.

Context precision

Were the retrieved chunks actually useful? Recall@3 is “did the right ID appear,” not “was chunk 2 noise.”

Latency SLO

A perfect ID at 40s is still a page. p95 is in the gate because ops agents are on-call tools.

This course

Labels have to match the gate

TLS expiry is tls-certificate-expiry, not auth 5xx. Slow queries are a gap (none). If the fixture lies, the gate punishes a correct agent.

Capstone

Checkout deploy → checkout-redis-pool, HITL true, keywords redis / connection. Miss that ID and correctness is 0 for the case — enough to sink the 0.85 average if it happens often.
