Why ops cannot skip this

AgentOps is the loop around an agent that can change production: ingest knowledge, orchestrate tools, stop at a human, ticket the action — and prove the loop still retrieves the right procedure after every change. Eval is the proof. The gate is the enforcement.

without eval you have a demo
without a gate you have a dashboard
with both you have a product
Intuition

Where eval sits in the loop

eval does not replace HITL
it decides whether the agent
is allowed to reach HITL
in production at all
Mechanics

Three places it runs

Console

Evaluation → Eval & Scores. Run Eval Suite on the live graph. Theater UI, per-case table, backend hint (Langfuse / Phoenix / MLflow by design).

GitHub

Required check eval-gate / golden-set on every PR to main. Artifact eval-report.json. Same runner as the console, MOCK_LLM=true.

LLM ops

D1 Langfuse datasets + scores. D2 Phoenix experiments. D3 MLflow. Judge scores land here so you can open a trace and see why a case failed.

Significance

What changes if you skip it

Silent RAG drift

Rechunk to 200 words, recall looks “fine” in chat, capstone ID falls out of top-3. On-call finds it at 2am.

Prompt roulette

A “clearer” system prompt swaps HITL off for P1 restarts. Unit tests still pass. The gate would not.

No promotion story

Governance four-eyes without a score is opinion. With a green golden-set you have evidence to show an auditor.

This course

Run it, then look at the check

Console: Evaluation → Eval & Scores → Run Eval Suite. GitHub: Actions → eval-gate. Capstone file is still checkout-redis-pool.md — eval is how we know Topic 1 stuck.

Capstone

Eight cases. TLS maps to the TLS runbook. Slow queries stay unmatched. Checkout deploy must HITL on Redis pool. When that suite is green, the agent is allowed onto main.
