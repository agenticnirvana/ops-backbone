What is eval
01 · Eval

A test suite for behavior

Evaluation is a fixed set of inputs, a live (or mocked) agent, and numeric scores you can compare across commits. The corpus is a golden set: alerts whose expected runbook_id, HITL flag, and keywords you already trust.

if you cannot fail it, it is not an eval

Intuition

Code tests vs agent tests

pytest: did query_metrics return a dict?

eval: did checkout P1 retrieve
checkout-redis-pool
and stop at HITL?
Mechanics

What / why / how

What

Offline regression: replay known incidents through the same LangGraph the console uses. Score retrieval, recommendation, tools, latency.

Why

LLMs and ANN indexes drift. A prompt tweak that “sounds better” can swap Redis pool for Postgres restart. You need a number, not a demo.

How

Load golden_alerts.json → graph.invoke per case → deterministic metrics + optional LLM-as-judge → averages vs thresholds.

In production

Where teams actually use it

Pre-merge

Every PR that touches prompts, chunking, or the graph must beat last week’s golden set.

Release

Staging promote waits on the same suite. Four-eyes is people; the gate is math.

Drift watch

Nightly replay against production traces. If recall drops after a reindex, you catch it before on-call does.

This course

Eight incidents, one verdict

Payment CPU, auth 5xx, TLS expiry, DB pool, slow queries (gap), checkout Redis — the same files you ingest in Topic 1. Eval is how we know the index is usable, not merely populated.

Capstone

eval-checkout-deploy must land on checkout-redis-pool with HITL. If it does not, the suite fails. That failure is the point.
