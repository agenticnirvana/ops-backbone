Eval gate
02 · Gate

A score that can refuse

An eval gate is a contract: averages must clear published bars or the change does not merge. It is the AgentOps analogue of a coverage gate or a security scan — except the subject is retrieval and remediation, not lines of code.

observability tells you what happened · a gate decides if it may ship

Mechanics

What / why / how

What

Boolean over averages: RAG recall ≥ 0.85, groundedness ≥ 0.80, correctness ≥ 0.85, tool accuracy ≥ 0.90, p95 ≤ 8s. One metric under and passed: false.

Why

Without a bar, evals become theatre. Teams will merge “small prompt edits” forever. The gate makes the golden set load-bearing.

How

GitHub Actions: build index → python -m evals.run_evals → parse JSON → exit 1 on fail. Required check on main: eval-gate / golden-set.

In production

Where the gate sits

Pull request

Required status check. Merge button stays grey until golden-set is green. Same idea as “tests must pass.”

Promote

Staging / production workflows re-run the suite before a SHA is blessed. Reviewers are humans; the gate is still the suite.

Fail closed

If the runner crashes, that is a fail, not a skip. You do not promote an agent you could not score.

This course

Check name: eval-gate / golden-set

Workflow .github/workflows/eval-gate.yml. Job golden-set. The ruleset on main will not merge a PR that skips it. Lint is not a substitute.

Capstone

A graph change that retrieves db-pool-exhausted for a Redis checkout P1 will drop correctness and trip the gate. That is the safety property Topic 1’s index is supposed to enable.
